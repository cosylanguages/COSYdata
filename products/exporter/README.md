# Exporter

The vocabulary as downloads. Renders `exports/manifest.json`: what can be
downloaded, how many rows, how big, and the hash that proves which version you
have.

## Files

| File | Role |
| --- | --- |
| `index.html` | Markup only. Empty containers, no counts, no links. |
| `exporter.css` | Layout and accents. Colour, spacing and type come from tokens. |
| `exporter.js` | Fetches the manifest and builds the links. |

## What it needs

```
products/exporter/            this folder, self-contained
shared/cosy-theme.js          theme toggle
shared/vendor/css/fonts.css   self-hosted fonts
shared/vendor/tokens.css      design tokens
shared/vendor/css/ecosystem-strip.css
shared/vendor/js/ecosystem-strip.js
exports/manifest.json         the download catalogue, generated by npm run build:exports
```

The files being downloaded (`exports/vocabulary.jsonl`, `exports/vocabulary.csv`,
`exports/by-language/<code>.csv`) are linked, not loaded, so they are not
dependencies of the page.

## Why the page lists nothing by hand

Every download link comes from the manifest, and every manifest entry carries a
row count, a byte size and a sha256. That means the page cannot advertise a file
that does not exist: `npm run check:exports` fails the build if the files on disk
differ from what the generator would write.

## Editing

```
npm run build:exports      # regenerate exports/ and the manifest
npm run check:exports      # fail if exports/ is stale
```

Never hand-edit anything in `exports/`. The CSV columns and their descriptions
live in `scripts/build-exports.cjs`.

## Checking

```
npm run test:exporter      # manifest vs disk, JSONL and CSV integrity, real browser render
```
