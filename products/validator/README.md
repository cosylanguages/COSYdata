# Validator

The quality audit, readable. Renders `reports/quality.json`: every rule the audit
enforces, what each rule found, and where the findings sit.

## Files

| File | Role |
| --- | --- |
| `index.html` | Markup only. Empty containers, no numbers, no rule names. |
| `validator.css` | Layout and accents. Colour, spacing and type come from tokens. |
| `validator.js` | Fetches the report and fills the containers. |

## What it needs

```
products/validator/           this folder, self-contained
shared/cosy-theme.js          theme toggle
shared/vendor/css/fonts.css   self-hosted fonts
shared/vendor/tokens.css      design tokens
shared/vendor/css/ecosystem-strip.css
shared/vendor/js/ecosystem-strip.js
reports/quality.json          the audit, generated by npm run build:quality-report
reports/quality-baseline.json accepted debt, linked from the rule catalogue
```

Paths are relative, so the folder works at this depth. To move it deeper, move
the `../../` prefix of the shared paths with it.

## Why it has no rule names in it

The page does not know what a rule means. `reports/quality.json` carries the
catalogue, which comes from `RULES` in `scripts/quality-audit.cjs`. Adding a rule
there is a one-line change and no change here. That is also why the page and the
CI gate cannot disagree: both call the same `collectFindings()`.

## Editing

```
npm run build:quality-report
```

Never hand-edit `reports/quality.json`; `npm run check:quality-report` fails if
it does not match the data.

## Checking

```
npm run test:validator     # report freshness, totals, and a real browser render
npm run test:quality       # the audit gate itself
```
