## Implication Summary for Dictionary UI Developers

1. **Filter Support**: Domain filters must support multi-tag comma-separated parsing and handle domain strings such as `general, relocation, spoken, travel, exam` as a set of individual domain flags (`general`, `relocation`, `spoken`, `travel`, `exam`).
2. **Domain String Mapping**: Search or filter controls should look for `travel` (not `travelling`) and `exam` (not `exam_preparation`).
3. **Required Core Content**: Every single entry in the database has populated `definitions` and `examples` arrays. The UI card can safely render definition and example blocks without fallback placeholding.
4. **Media Fallbacks**: Neither `audio` nor `image` properties are currently populated in any JSON entry file. The UI should hide media placeholders or utilize browser speech synthesis and entry `emoji` strings for visual context.
5. **Grammar & Related Forms**: `related_forms` appears in ~2.6% of entries (mostly Italian, Russian, Greek, and French). The dictionary layout should render a "Related Conjugations / Forms" section conditionally when the array is present.
